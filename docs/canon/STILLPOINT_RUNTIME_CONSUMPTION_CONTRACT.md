# StillPoint Runtime Consumption Contract

**Status:** Canon-consumption contract  
**Authority:** Subordinate to `docs/canon/STILLPOINT_CREATED_REALITY_CANON.md`  
**Purpose:** Prevent theological canon, historical truth, current evidence, and executable authority from collapsing into one another.

## 1. No authority transfer by description

A claim, memory, document, diagnosis, prediction, historical record, or canonical sentence may inform reasoning. None may create executable authority merely because it is true, canonical, recent, or highly confident.

Preserve the separation:

**evidence != warrant != execution != completion**

and:

**description != identity**

## 2. Historical truth and current truth must coexist

The runtime must preserve both:

- what was true / what happened; and
- what is true now.

A prior true state may remain immutable history while losing present jurisdiction.

Example model:

- historical: `Jesus died` -> remains true;
- prior-current: `Jesus is dead` -> valid only while current evidence supports it;
- later-current: resurrection evidence invalidates the continuing present-tense description without erasing the historical event.

This is the operating meaning of:

> StillPoint does not limit truth. It limits the jurisdiction of a true description over changing reality.

## 3. Temporal non-inheritance

A claim does not retain present authority merely because it was once true.

Systems must support:

- observation time;
- effective time;
- last-confirmed time;
- supersession / expiry;
- contradiction and correction;
- re-entry when new evidence appears.

Stale present-tense claims must not be promoted into permanent identity.

## 4. Jurisdictional non-inheritance

A valid claim in one domain does not silently create authority in another.

Examples:

- knowledge does not create permission;
- diagnosis does not create identity ownership;
- memory does not create current-state authority;
- approval does not create broader scope;
- one successful action does not authorize another action;
- canon does not self-execute.

## 5. Release preserves history

When a claim expires or a warrant releases, history is not deleted.

The system should preserve provenance, evidence, lineage, and the reason a claim or authority ceased to govern.

Canonical image:

> The wounds remain; the nails do not.

The implementation analogue is **memory without captivity**: retain evidence; release obsolete jurisdiction.

## 6. Continuing evidence

Present authority must remain reachable by later evidence.

A successful description must not acquire permanent jurisdiction over the thing it describes.

Therefore:

- later evidence can challenge current descriptions;
- current descriptions can be superseded without falsifying prior history;
- identity should not be permanently derived from an expired state;
- released authority cannot be revived merely by citing old evidence;
- new authority requires a new present warrant.

## 7. Calendar and StillPoint consumption

The 364-day / 52-week surface remains a canonical calendar contract where already enacted.

The weekly StillPoint architecture is local Friday sunset through Sabbath to Sunday sunrise as a protected-time / observational layer. It must not mutate the immutable civil grid.

The theological supreme form—Christ's death-to-resurrection passage—is canonical doctrine, not a software clock interval to be inferred or simulated.

## 8. Source discipline

Maintain:

**SOURCE -> interpretation / synthesis -> CURRENT CANON -> implementation**

Software may encode CURRENT CANON but may not promote itself into SOURCE.

New research may produce evidence or proposals. It may not silently mutate canon.

## 9. Governing runtime principle

Finite authority must be able to stop.

A runtime consistent with StillPoint should prefer structures in which:

- warrants expire;
- descriptions can be superseded;
- actions remain scope-bound;
- evidence remains inspectable;
- completion can release authority;
- recovery does not resurrect consumed authority;
- correction remains reachable;
- relation survives without possession.

This document governs consumption of the StillPoint created-reality canon by RobertOS, StillPoint Core, StillPointOS, Calendar/Clock layers, and related runtime surfaces.
