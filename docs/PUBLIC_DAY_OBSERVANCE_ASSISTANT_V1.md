# StillPoint public day and observance assistant — bounded read-only v1

**Status:** public Canonical Core feature candidate. A feature branch or successful
build is not a live release. After approval and merge, confirm the deployed
GitHub Pages URL, exact source SHA, and actual browser behavior separately.

## New, useful operations

The existing Python assistant already answers individual published Common
Calendar days with `calendar.day.read`. This increment adds a **distinct,
explicitly permission-gated** `calendar.observances.read` capability, plus a
day-question form on the public browser site.

Examples of accepted complete Python Core requests:

- `What is the Common Calendar date for 2026-11-17?`
- `Show Common Calendar day 364 of 2075.`
- `Explain Common Calendar observances for 2026-11-17.`
- `Explain Common Calendar observances on Common day 1 of 2027.`

For example, using the matching installed public Core:

```sh
stillpoint ask "Explain Common Calendar observances on Common day 1 of 2027." > answer.json
stillpoint verify-answer answer.json
```

The Python path checks the caller's explicitly supplied public-read capability
before any calendar projection, then uses the existing
`calendar_day_payload()`. The output contains the **Core-defined** observance
name, jurisdiction, rule, projection status, and any present Core note and
source references. An empty day reports no named observances; it does not
invent one or imply Sabbath/protected-time overlays disappeared. The verifier
re-runs the same bounded request and compares the complete result, answer,
source-byte fingerprints, scope, and receipt; merely rehashing a falsified
receipt cannot make it valid.

Requests for unpublished Common year 2076, ordinal 365, invalid ordinary dates,
unbounded prompts, or consequential actions fail closed. Source references are
**references recorded in the Core**, not independent textual exegesis, proof of
religious authority, or a civil-law enactment.

## Static-browser implementation and evidence layers

The browser's new day-question form accepts **only** explicit Gregorian
YYYY-MM-DD or Common year/ordinal questions for day details and observances.
The 364-day Common surface, March 25 sacred source-year anchor, 2027 selected
Jubilee epoch, overlapping 49-year cycle, and 2026–2075 finite map are
unchanged. The external Gregorian date labels remain translations, not
governing Common coordinates.

Every annual static shard is generated by `calendar_day_payload()`; its
observance entries now preserve the existing published Core source references,
rule, note and status without any independent JavaScript calendar calculation.
The browser computes **SHA-256 on the fetched annual JSON bytes** and rejects
a mismatch against the site's published manifest before presenting the
day/observance details. It keeps the existing week-answer receipt mechanism
separate.

**Do not mislabel the two types of verification:**

1. The browser's year-shard check confirms that the downloaded Core-generated
   year file agrees with the site's manifest. The manifest is not signed.
2. `stillpoint verify-answer` on an actual `stillpoint ask` JSON receipt
   performs independent reproduction against the exact public Python source
   and calendar publication. The new browser day explanation is **not itself
   a Python answer receipt**. The page displays the exact CLI request so
   anyone with the matching Core can generate and verify one.

The site has no backend model, browser secrets, private source access,
location collection, user login, network action adapter, payment, or authority
to rewrite the calendar. It does not compute local sunrise/sunset times.
A source reference is not a claim that every community must follow an
observance, nor that an external Gregorian legal holiday has been changed.

## Verification and release gates

```sh
python -m unittest tests.test_public_assistant -v
python -m unittest discover -s tests/calendar_core -p 'test_public_calendar_site_export.py' -v
python tools/export_public_calendar_site.py --output /tmp/stillpoint-public-day-evidence
```

The website export test also runs the **actual browser JavaScript parser** in
Node.js when Node is available; GitHub's public Ubuntu runner supplies Node.
An additional live-browser acceptance must cover both question modes, a civic
marker with no textual refs, a sacred marker with explicit references and note,
a date with no observances, a cross-year ordinary-date translation, Common
2075/364, rejected 2076, tamper-rejected year shard, keyboard, and narrow viewport.

The feature changes only the existing public Canonical Core; there are no
private code imports. RobertOS, StillPointOS, StillPoint and writing-corpus
remain private and unchanged. Public Core CI never qualifies their live
private cross-system integration. No new workflow, repository, or paid runner
is required.
